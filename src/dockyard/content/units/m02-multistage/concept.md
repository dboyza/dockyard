## Stages are separate filesystem roots

Each FROM starts a new stage.
A later stage receives files from an earlier stage only when you copy them explicitly.
This lets compilers, development dependencies, and temporary artifacts stay out of the final runtime image.
Multi-stage builds do not automatically guarantee a small or secure result; a broad COPY can bring unwanted files back in.

For Dispatch, the first stage checks that the supplied Python module compiles.
The runtime stage needs the original app.py and VERSION, but not the verification directory or generated bytecode.
This is intentionally a small example of the same artifact boundary used by compiled applications.

## Worked example: copy a selected output

```dockerfile
FROM build-base AS build
WORKDIR /build
COPY . .
RUN compile-tool --output /out/report
FROM runtime-base
COPY --from=build /out/report /usr/local/bin/report
USER 10001:10001
CMD ["/usr/local/bin/report"]
```

The names in this conceptual example stand for appropriate real images and tools.
The important property is that the runtime stage receives one selected artifact rather than the entire build filesystem.
Your task uses the supplied Python base and real Python compilation instead.

## Root is a default, not an application requirement

Many images start as UID 0 unless configured otherwise.
A container's root process has important restrictions compared with unrestricted host root, but it still has more authority inside its container than this API needs.
Use a numeric UID and GID to make the runtime identity explicit.
A user record in `/etc/passwd` may be helpful for some applications, but this supplied API does not require one.

Copied files must be readable by the runtime identity.
`COPY --chown=10001:10001` assigns ownership while constructing the image.
A non-root API can listen on port 8080 without needing a privileged-port capability.
It should not need to install packages or rewrite its source when starting.

## Verify the actual process

```sh
docker exec "$DOCKYARD_CONTAINER" python -c 'import os; print(os.getuid())'
curl --fail "http://127.0.0.1:$DOCKYARD_PORT/healthz"
```

Inspecting the process environment and making a request together catches a common mistake: writing a correct final stage but running an old image or container.
Read-only filesystems, capability reduction, and resource limits arrive in Module 6.
